# Mogged Keyboard

Клавиатура для Android: раскладки RU и EN, своё оформление, жесты,
умная пунктуация, шаблоны и история буфера. Всё хранится на телефоне,
сеть нужна только для проверки обновлений.

Файл описывает проект целиком: его достаточно, чтобы собрать, проверить
и не сломать правила. Подробности и планы — в `docs/ROADMAP.md`.

## 1. Проект

- **Название:** Mogged Keyboard, репозиторий `itzme-work/MoggedKeyboard`.
- **Пакет:** `com.mogged.keyboard`, один модуль `:app`.
- **Язык интерфейса:** русский, без технических слов (см. правила).
- **Стек:** Kotlin 1.9.24, Android Gradle Plugin 8.5.2, Gradle 8.7,
  Java 17, Material 3 (`com.google.android.material:material:1.12.0`),
  AndroidX (`core-ktx`, `appcompat`, `core-splashscreen`, `exifinterface`,
  `recyclerview:1.3.2` — список окна истории).
- **Версии Android:** `minSdk 26` (Android 8.0), `targetSdk 34`,
  `compileSdk 34`.
- **Тесты:** JUnit 4; чистая логика без Android проверяется на JVM.

## 2. Карта модулей

`app/src/main/java/com/mogged/keyboard/`

- `MoggedKeyboardService.kt` — сама клавиатура (`InputMethodService`):
  клавиши, ввод, Shift/Caps, меню, всплывающие окна, темы, размеры.
- `Layouts.kt` — раскладки RU, EN, символы и альтернативы клавиш.
- `TextState.kt` — Shift, Caps Lock и автозаглавная (чистая логика).
- `Widths.kt` — ширина блока клавиш, высота на телефоне и планшете,
  режим одной руки (чистая логика).
- `Prefs.kt` — настройки в `SharedPreferences` (файл `mogged`);
  `saveTemplates()` пишет шаблоны и возвращает результат.
- `Backup.kt` — `Settings`, экспорт и импорт JSON, значения по умолчанию.
- `Look.kt` — акценты, пресеты, формы клавиш, контраст (чистая логика).
- `Palette.kt` — производные цвета ARGB: прозрачность, смешивание, AMOLED.
- `Panel.kt` — состав и порядок кнопок панели инструментов.
- `Punctuation.kt` — умная пунктуация и автопробел, защищённые поля.
- `Templates.kt` — шаблоны-сокращения и их лимиты.
- `Gestures.kt` — жесты по пробелу (язык, каретка).
- `Haptics.kt` — характер вибрации и усиление на Shift/Enter/пробел.
- `ClickSound.kt` — короткий звук нажатия, WAV собирается в памяти.
- `Images.kt` — своя картинка фона: поворот, заполнение, уменьшение,
  размытие, очередь работы и подписка на результат.
- `PhotoTone.kt` — средний тон фото с затемнением, один расчёт на картинку.
- `MainActivity.kt` — настройки приложения по разделам.
- `MiniKeyboardPreview.kt` — живой мини-предпросмотр клавиатуры.
- `SandboxActivity.kt` — «Песочница»: поле ввода с настоящей клавиатурой.
- `UpdateManager.kt` — проверка обновлений через GitHub Releases (`latest`),
  лимиты размера, SHA-256 и сверка сертификата.
- `Officiality.kt` — отпечаток релизного сертификата и признак
  «официальная сборка» (чистая логика).
- `ClipboardHistory.kt` — история буфера: лимиты, повторы, закрепление,
  поиск, JSON, одноразовые коды.
- `ClipStore.kt` — файл истории: AES-GCM, ключ из Keystore, `shouldWipe`,
  перевыпуск ключа без потери записей, каскад ключей (`read`, `Loaded`).
- `ClipCache.kt` — история в памяти: повтор чтения после неудачи, слияние
  записей, накопленных пока файл был недоступен, и запись их на диск
  (`saver`).
- `TemplateStore.kt` — шаблоны отдельным шифрованным файлом (свой ключ);
  набор кэшируется в памяти, файл читается только при пустом кэше.
- `PanelBar.kt` — правила верхней панели: ширина окна, от 600 dp без
  прокрутки, 5 или 8 чипов, область касания.
- `ClipTime.kt` — подпись времени копирования.
- `PanelMode.kt` — режимы строки над клавишами и переходы между ними.
- `Changelog.kt` — список изменений в приложении и `VERSION`.
- `MoggedApp.kt` — ночной режим, опции динамических цветов, миграции настроек.

Тесты — `app/src/test/java/com/mogged/keyboard/`: по одному файлу на
каждую чистую логику (`WidthsTest`, `PanelTest`, `PanelModeTest`,
`PunctuationTest`, `PaletteTest`, `LookTest`, `HapticsTest`, `GesturesTest`,
`LayoutsTest`, `TemplatesTest`, `TextStateTest`, `BackupTest`,
`PhotoToneTest`, `KeyAlphaTest`, `ClipboardHistoryTest`, `ClipStoreTest`,
`ClipCacheTest`, `PanelBarTest`, `UpdateManagerTest`, `OfficialityTest`).

## 3. Сборка

Собирает только CI: на телефоне нет ни JDK, ни Gradle, ни Android SDK.

- `.github/workflows/check.yml` — на каждый push и pull request: служебная
  проверка дерева, сверка версий, тесты и lint.
- `.github/workflows/build.yml` — вручную: подписанный APK, релиз `latest`
  с `MoggedKeyboard.apk` и `version.json`.
- `.github/workflows/verify-deps.yml` — вручную: контрольные суммы
  библиотек Gradle (`verification-metadata.xml`) артефактом.

Окружение CI:

- `ubuntu-latest`, Temurin **JDK 17** (`actions/setup-java@v4`);
- **Gradle 8.7** скачивается с официальных `services.gradle.org`
  и `downloads.gradle.org`; сторонних зеркал в дереве нет; сумма SHA-256
  `544c35d6bd849ae8a5ed0bcea39ba677dc40f49df7d1835561582da2009b961d`
  проверяется всегда;
- Android SDK с раннера, `compileSdk 34`, `build-tools` ставятся Gradle;
- ключ подписи приходит в CI из настроек репозитория, в дереве его нет.

Локально (нужны JDK 17 и Android SDK 34):

```sh
sh gradlew testReleaseUnitTest lintRelease
```

`gradlew` в репозитории — тонкая обёртка: если Gradle 8.7 не установлен,
она скачивает тот же дистрибутив и сверяет сумму.

Значок для README и релиза (`docs/icon-512.png`) рисуется awk:

```sh
sh tools/make-icon.sh
```

`versionCode` — номер запуска CI (`GITHUB_RUN_NUMBER`), поэтому каждая
сборка «новее» предыдущей и обновление ставится поверх.

Заливка файлов, ключ подписи и настройки репозитория в репозитории не
описаны: это служебное, оно живёт в локальных заметках вне проекта.


## 4. Правила

1. **Версия в трёх местах** — `appVersionName` в `app/build.gradle.kts`,
   `Changelog.VERSION` в `Changelog.kt`, `"versionName"` в `release.json`.
   Плюс строка «Версия» в разделе 6 этого файла. CI падает при расхождении.
2. **Ключи и пароли не попадают в репозиторий.** В коде и файлах их быть
   не может; CI берёт ключ подписи из настроек репозитория.
3. **Тексты для пользователя — без технических слов.** Не «EXIF»,
   «центр-кроп», «эмбиент», «билд», а «фото с камеры не лежат боком»,
   «картинка заполняет фон». Список изменений читает обычный человек.
   Единицы в подписях ползунков (dp) — можно, это шкала, а не жаргон.
4. **Рискованные функции выключены по умолчанию** (умная пунктуация,
   шаблоны) и **не работают в паролях, адресах, почте, путях, флагах
   и терминалах** — см. `Punctuation.protectedField`.
5. **Клавиатура не использует сеть.** Сеть есть только у проверки
   обновлений в настройках и только по нажатию или при включённой
   автопроверке.
6. **Новая настройка** — это всегда четыре шага: поле в `Prefs`,
   значение по умолчанию в `Backup.DEFAULT` (и в экспорте/импорте),
   сброс в своём разделе настроек, тест на новую логику.
7. **Логику выносить из Android.** Расчёты (ширина, цвета, пунктуация,
   шаблоны, панель) живут в объектах без `Context` — их проверяют тесты.
8. **Файлы пользователя не покидают телефон**: картинка фона хранится
   в `filesDir`, в резервную копию уходит только флаг.

## 5. Процесс

1. ТЗ на версию (что меняем и почему).
2. Правки кода, тестов и текстов; версия поднята в трёх местах.
3. Зелёные «Проверки» и «Build APK» — версия считается выложенной.
4. Ревью: список замечаний на следующую версию. Блокеров нет — можно
   выпускать; блокер — новая версия сразу.
5. Правки после ревью — уже следующей версией, а не перезаписью релиза.

Известные ошибки:

- Признак «официальная сборка» сравнивает отпечаток с зашитым в код:
  подделку можно обойти правкой исходников, но честный пользователь увидит
  предупреждение, а обновление с другим ключом всё равно не поставится.
- Проверка подписи при обновлении видит только установленную подпись:
  на самой первой установке извне сравнивать не с чем, и обновление
  проходит обычным путём Android.
- `java.net` в `MainActivity.kt` разрешён проверкой CI, хотя сетевого
  кода там нет: ограничение на будущее, а не текущая дыра.
- Хэши Gradle-зависимостей ещё не лежат в дереве: файл
  `gradle/verification-metadata.xml` готовит ручная сборка «Хэши
  зависимостей» (`verify-deps.yml`), пока его не закоммитили, CI
  библиотеки не сверяет. Причина из ROADMAP («создаёт только локальный
  Gradle») неверна — runner умеет то же самое.
- «Назад» закрывает окно истории не на всех прошивках: система обычно
  отдаёт клавишу приложению. Кнопка «Закрыть» работает всегда.
- Свёрнутость строки над клавишами не сохраняется между показами
  клавиатуры — сохраняется только режим (так в ТЗ).

### Проблемы из ревью 0.14.0 (пункты 1–5)

1. **Хэши Gradle-зависимостей не добавлены.** Причина в ROADMAP («создаёт
   только локальный Gradle») неверная: `--write-verification-metadata
   sha256` работает и на runner GitHub. Готово: `verify-deps.yml`
   (ручной запуск) прогоняет тесты, lint и release-сборку, пишет
   `gradle/verification-metadata.xml` и выкладывает артефактом. Осталось
   скачать артефакт, положить файл в дерево и залить.
2. **Шаблоны читались слишком часто.** `Prefs.templates` звал
   `TemplateStore.read` на каждое обращение, а служба — в `loadPrefs()`
   на каждый показ клавиатуры и каждое изменение настроек (каждый шаг
   ползунка): поход в Keystore в главном потоке. Закрыто в 0.14.1: файл
   читается, только если `TemplateStore.cached()` ещё пуст.
3. **Ошибка записи шаблонов терялась.** Сеттер `templates` игнорировал
   результат `TemplateStore.save`, `Backup.applyTo` — тоже, и правка
   пропадала молча. Закрыто: `Prefs.saveTemplates()` и `Backup.applyTo()`
   возвращают результат, `MainActivity` показывает ошибку.
4. **Записи из памяти не сохранялись сразу.** После слияния в
   `ClipCache.ensure` они жили только в памяти до следующего события.
   Закрыто: `ensure()` пишет их через `saver` (`ClipStore.save`).
5. **Формулировка про скриншоты.** `FLAG_SECURE` стоит только на окне
   клавиатуры, поле приложения на снимке остаётся видимым. Закрыто:
   в списке изменений — «клавиатура на скриншотах скрыта».

Не проверено на устройстве: окно истории с поиском, перетаскиванием
и отменой, панель во всю ширину при ширине клавиш 60% и одной руке,
вырез в альбомной ориентации, `FLAG_SECURE`, шаблоны после миграции,
сохранение на телефоне без блокировки экрана, планшет 1280×800.

## 7. Поддержка

Каждое обновление обязано:

1. поменять строку «Версия» в разделе 6 и дописать сделанное;
2. дописать принятые решения в `docs/ROADMAP.md`;
3. синхронизировать версию в трёх местах из правила 1.

CI проверяет, что версия в этом файле совпадает с `appVersionName`
(шаг «Проверка версий» в `check.yml` и `build.yml`), — расхождение
роняет сборку.
