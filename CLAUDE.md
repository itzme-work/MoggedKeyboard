# Mogged Keyboard

Клавиатура для Android: раскладки RU и EN, своё оформление, жесты,
умная пунктуация и шаблоны. Всё хранится на телефоне, сеть не используется.

Файл описывает проект целиком: его достаточно, чтобы собрать, проверить
и не сломать правила. Подробности и планы — в `docs/ROADMAP.md`.

## 1. Проект

- **Название:** Mogged Keyboard, репозиторий `itzme-work/MoggedKeyboard`.
- **Пакет:** `com.mogged.keyboard`, один модуль `:app`.
- **Язык интерфейса:** русский, без технических слов (см. правила).
- **Стек:** Kotlin 1.9.24, Android Gradle Plugin 8.5.2, Gradle 8.7,
  Java 17, Material 3 (`com.google.android.material:material:1.12.0`),
  AndroidX (`core-ktx`, `appcompat`, `core-splashscreen`, `exifinterface`).
- **Версии Android:** `minSdk 26` (Android 8.0), `targetSdk 34`,
  `compileSdk 34`.
- **Тесты:** JUnit 4; чистая логика без Android проверяется на JVM.

## 2. Карта модулей

`app/src/main/java/com/mogged/keyboard/`

- `MoggedKeyboardService.kt` — сама клавиатура (`InputMethodService`):
  клавиши, ввод, Shift/Caps, меню, всплывающие окна, темы, размеры.
- `Layouts.kt` — раскладки RU, EN, символы и альтернативы клавиш.
- `TextState.kt` — Shift, Caps Lock и автозаглавная (чистая логика).
- `Widths.kt` — ширина блока клавиш, высота на телефоне и планшете,
  режим одной руки (чистая логика).
- `Prefs.kt` — настройки в `SharedPreferences` (файл `mogged`).
- `Backup.kt` — `Settings`, экспорт и импорт JSON, значения по умолчанию.
- `Look.kt` — акценты, пресеты, формы клавиш, контраст (чистая логика).
- `Palette.kt` — производные цвета ARGB: прозрачность, смешивание, AMOLED.
- `Panel.kt` — состав и порядок кнопок панели инструментов.
- `Punctuation.kt` — умная пунктуация и автопробел, защищённые поля.
- `Templates.kt` — шаблоны-сокращения и их лимиты.
- `Gestures.kt` — жесты по пробелу (язык, каретка).
- `Haptics.kt` — характер вибрации и усиление на Shift/Enter/пробел.
- `ClickSound.kt` — короткий звук нажатия, WAV собирается в памяти.
- `Images.kt` — своя картинка фона: поворот, заполнение, уменьшение,
  размытие, очередь работы и подписка на результат.
- `PhotoTone.kt` — средний тон фото с затемнением, один расчёт на картинку.
- `MainActivity.kt` — настройки приложения по разделам.
- `MiniKeyboardPreview.kt` — живой мини-предпросмотр клавиатуры.
- `SandboxActivity.kt` — «Песочница»: поле ввода с настоящей клавиатурой.
- `UpdateManager.kt` — проверка обновлений через GitHub Releases (`latest`).
- `Changelog.kt` — список изменений в приложении и `VERSION`.
- `MoggedApp.kt` — ночной режим и опции динамических цветов.

Тесты — `app/src/test/java/com/mogged/keyboard/`: по одному файлу на
каждую чистую логику (`WidthsTest`, `PanelTest`, `PunctuationTest`,
`PaletteTest`, `LookTest`, `HapticsTest`, `GesturesTest`, `LayoutsTest`,
`TemplatesTest`, `TextStateTest`, `BackupTest`, `PhotoToneTest`,
`KeyAlphaTest`).

## 3. Сборка

Собирает только CI: на телефоне нет ни JDK, ни Gradle, ни Android SDK.

- `.github/workflows/check.yml` — на каждый push и pull request: тесты
  и lint. Здесь же сверка версий и версии в этом файле.
- `.github/workflows/build.yml` — вручную (или из `upload-to-github.sh`):
  подписанный APK, релиз `latest` с `MoggedKeyboard.apk` и `version.json`.

Окружение CI (оттуда же брать версии для локальной сборки):

- `ubuntu-latest`, Temurin **JDK 17** (`actions/setup-java@v4`);
- **Gradle 8.7** скачивается с зеркал и сверяется по SHA-256
  `544c35d6bd849ae8a5ed0bcea39ba677dc40f49df7d1835561582da2009b961d`;
- Android SDK с раннера, `compileSdk 34`, `build-tools` ставятся Gradle;
- ключ подписи — только из секретов `KEYSTORE_BASE64`,
  `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.

Локально (нужны JDK 17 и Android SDK 34):

```sh
sh gradlew testReleaseUnitTest lintRelease
```

`gradlew` в репозитории — тонкая обёртка: если Gradle 8.7 не установлен,
она скачивает тот же дистрибутив и сверяет сумму. При установленном
Gradle хватает `gradle testReleaseUnitTest lintRelease`; после
`chmod +x gradlew` работает и `./gradlew`.

Архив исходников для проверки собирает GitHub (локального zip нет):

```sh
sh tools/make-zip.sh          # имя по версии из app/build.gradle.kts
```

Значок для README и релиза (`docs/icon-512.png`) рисуется тем же awk:

```sh
sh tools/make-icon.sh
```

`versionCode` — номер запуска CI (`GITHUB_RUN_NUMBER`), поэтому каждая
сборка «новее» предыдущей и обновление ставится поверх.

## 4. Правила

1. **Версия в трёх местах** — `appVersionName` в `app/build.gradle.kts`,
   `Changelog.VERSION` в `Changelog.kt`, `"versionName"` в `release.json`.
   Плюс строка «Версия» в разделе 6 этого файла. CI падает при расхождении.
2. **Ключи и пароли — только в секретах Actions.** В репозитории нет
   ни ключа подписи, ни паролей; в коде их быть не может.
3. **Тексты для пользователя — без технических слов.** Не «EXIF»,
   «центр-кроп», «эмбиент», «билд», а «фото с камеры не лежат боком»,
   «картинка заполняет фон». Список изменений читает обычный человек.
   Единицы в подписях ползунков (dp) — можно, это шкала, а не жаргон.
4. **Рискованные функции выключены по умолчанию** (умная пунктуация,
   шаблоны) и **не работают в паролях, адресах, почте, путях, флагах
   и терминалах** — см. `Punctuation.protectedField`.
5. **Клавиатура не использует сеть.** Сеть есть только у проверки
   обновлений в настройках и только по нажатию или при включённой
   автопроверке.
6. **Новая настройка** — это всегда четыре шага: поле в `Prefs`,
   значение по умолчанию в `Backup.DEFAULT` (и в экспорте/импорте),
   сброс в своём разделе настроек, тест на новую логику.
7. **Логику выносить из Android.** Расчёты (ширина, цвета, пунктуация,
   шаблоны, панель) живут в объектах без `Context` — их проверяют тесты.
8. **Файлы пользователя не покидают телефон**: картинка фона хранится
   в `filesDir`, в резервную копию уходит только флаг.

## 5. Процесс

1. ТЗ на версию (что меняем и почему).
2. Правки кода, тестов и текстов; версия поднята в трёх местах.
3. Заливка `sh upload-to-github.sh` (запускает «Build APK»).
4. Зелёные «Проверки» и «Build APK» — версия считается выложенной;
   APK и ZIP исходников скачиваются в Downloads.
5. Ревью: список замечаний на следующую версию. Блокеров нет — можно
   выпускать; блокер — новая версия сразу.
6. Правки после ревью — уже следующей версией, а не перезаписью релиза.

## 6. Состояние

**Версия: 0.12.0** «Буфер обмена».

Сделано:

- История буфера: `ClipboardHistory` (30 записей, 10 закреплённых,
  5000 символов, склейка повторов, поиск, JSON), `ClipStore` (AES-GCM,
  файл в `noBackupFilesDir`, ключ из Keystore, при потере ключа история
  стирается), `ClipTime` (метка времени).
- `MoggedKeyboardService`: слушатель `OnPrimaryClipChangedListener`, пока
  клавиатура активна и поле не защищено, плюс чтение буфера при открытии
  панели. `captureClip()` отсекает пароли, числа, телефоны и почту через
  `Punctuation.protectedField`, клипы с `EXTRA_IS_SENSITIVE` и инкогнито.
  Попап истории у кнопки панели: тап вставляет текст, долгое нажатие
  закрепляет, свайп в сторону удаляет. Кнопка `Panel.HISTORY` с векторной
  иконкой; в инкогнито и защищённых полях скрыта.
- `MainActivity` и `section_input.xml`: переключатель истории, срок
  (1 час / 1 день / никогда), «Открыть историю» с поиском, «Очистить всё»
  с подтверждением; новые настройки входят в сброс раздела «Ввод».
  `Prefs.clipHistory`/`clipRetention`, в `Backup` только флаг и срок.
- `Widths.contentWidthDp` и `MAX_EDGE_DP`: формула ширины с отступом
  вынесена из сервиса; тесты 100% и 50% при отступе 0 и 12, минимум 240dp.
- 0.11.1: значок M, отступ у краёв 0–12dp, картинка не теряется при
  сворачивании, высота не пишется при открытии, `Backup.snap`.
- 0.11.0: вся ширина окна, высота по планшету, крупнее буквы, окна
  альтернатив и одной руки от ширины окна, один поток картинки.

Дальше (0.13.0):

- разделённая раскладка от 840dp (зазор по центру 15–30%);
- свои раскладки: пользователь задаёт ряды;
- импорт шаблонов из текстового файла.

Известные ошибки: нет.

Не проверено на устройстве: история буфера целиком (захват, вставка,
закрепление, свайп, инкогнито), планшет в двух ориентациях, монохромный
значок. На телефоне с жестами проверить отступ 0/12, значок на рабочем
столе и сворачивание при обработке картинки.

## 7. Поддержка

Каждое обновление обязано:

1. поменять строку «Версия» в разделе 6 и дописать сделанное;
2. дописать принятые решения в `docs/ROADMAP.md`;
3. синхронизировать версию в трёх местах из правила 1.

CI проверяет, что версия в этом файле совпадает с `appVersionName`
(шаг «Проверка версий» в `check.yml` и `build.yml`), — расхождение
роняет сборку. Этот файл входит в архив `tools/make-zip.sh`, потому что
архив — это ветка `main` целиком.
